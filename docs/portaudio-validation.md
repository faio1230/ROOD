# PortAudio実機検証

対象はPortAudio v19.7.0です。`scripts/bootstrap-portaudio.ps1` はWASAPIだけを有効にします。`scripts/bootstrap-portaudio-asio.ps1` はSteinberg公式ASIO SDK 2.3.4をローカルで使い、ASIOとWASAPIを有効にした**検証用**ビルドを作ります。この検証版には、`ROOD_ASIO_ONLY` で単一ドライバに絞る[小さなパッチ](../patches/portaudio-v19.7.0-asio-allowlist.patch)を当てています。

## 初回の観測

- デバイス列挙: Windows WASAPI出力14件、各デバイスのPortAudio上限は2チャンネル。
- VB-Audio Virtual Cable（列挙時のID 12）、48 kHz / float32 / 2 ch: `Pa_IsFormatSupported` は共有・排他とも対応。
- 3秒間の無音出力: 共有303 callback、underflow 0、DAC時刻の後退0、報告された出力遅延22 ms。
- 3秒間の無音出力: 排他302 callback、underflow 0、DAC時刻の後退1、報告された出力遅延12 ms。
- 同じWASAPI排他での5秒再試験: 502 callback、underflow 0、DAC時刻の後退1。最初の後退はcallback 2で約1.6 msでした。
- ASIO全ドライバを読み込む通常ビルドはこのPCでデバイス列挙が停止しました。登録されたどのドライバで止まるかは未特定です。検証用パッチで1ドライバに限定すると列挙できました。
- VB-Matrix VASIO-8: 8チャンネル、44.1 kHzで5秒の無音出力が成功（243 callback、underflow 0、時刻後退0）。報告遅延は約23.22 ms。
- VB-Matrix VASIO-32: 16チャンネルと32チャンネル、44.1 kHzでそれぞれ3秒の無音出力が成功（各146 callback、underflow 0、時刻後退0）。報告遅延は約23.22 ms。
- VASIO-8の48 kHz / 8チャンネルは形式照会が対応と返しましたが、`Pa_OpenStream` は `Invalid sample rate` で失敗しました。
- MSVC版PortAudioでも、VASIO-32の32チャンネル、44.1 kHzで3秒の無音出力が成功しました。146 callback、underflow 0、DAC時刻の後退0、報告遅延23.22 msでした。
- その後、コールバックが消費したフレーム総数を壁時計で割って確認しました。VASIO-32の32チャンネル・44.1 kHzは10秒で247,296フレーム、**実効約24,528 frames/s**でした。PortAudioの報告レート44,100 Hzと大きく異なり、underflowと時刻後退は0でした。VASIO-32の16チャンネルとVASIO-8の8チャンネルも約24,400 frames/sです。同じ計測をした別の仮想WASAPI出力は48,000 Hzに対し約48,085 frames/sでした。PortAudioが返す時刻の連続性だけではクロック速度の誤りを発見できません。
- MSVC版WASAPIでVB-Audio Virtual Cable（ID 12）の共有・排他を48 kHz / 2チャンネルで3秒ずつ再試験しました。共有303 callback、排他302 callback、どちらもunderflow 0。DAC時刻はcallback 2で共有が約8.0 ms、排他が約1.6 ms後退しました。報告遅延は共有22 ms、排他12 msでした。

WASAPI排他モードで時刻が後退したため、`outputBufferDacTime` を無条件に連続時刻として使う設計にはしません。ASIOについても `Pa_IsFormatSupported` の結果だけでは開設可否を決められません。これらの数値はドライバ・機器・同時利用状況に依存します。無音出力が成功しても、各チャンネルの実際の行き先、物理DAC時刻、長時間ドリフトは未検証です。

## 採用を確定するための検証

### SRT受信から音声出力までの短時間試験

MPEG-TSの映像1本、ステレオ音声1本、5.1音声1本をSRTで5秒間送り、切断後に別の3秒入力を再接続するループバック試験を追加しました。ROODは48 kHz音声を時刻付きキューに配置し、任意のトラック／チャンネル経路でPortAudioへ出力します。このPCのVB-Audio仮想デバイスで、WASAPI共有・排他の2チャンネル出力、およびASIOの32チャンネル・44.1 kHz出力を確認しました。ASIOでは48→44.1 kHzの変換を通しています。いずれもPortAudioコールバックがデコード済みフレームを消費し、短時間の試験ではデバイスunderflowは0でした。

5.1トラックの6番目のチャンネルには330 Hzの識別信号を入れ、OMT受信プローブで指定した2番目の出力チャンネルに非無音サンプルが届くことを確認しました。PortAudio側の物理出力先はこの試験だけでは確認できません。ASIOは検証用の単一ドライバ許可パッチを使っています。出力時刻後退はWASAPIで観測されました。クロック差補正は初期実装のみで、1時間以上の同期・機器切断復帰は引き続き未検証です。

ASIOの30秒連続受信では、VASIO-32の申告44.1 kHzと実効約24.6 kframes/sの差により、音声フレームの大半が時刻付きキューから破棄され、Spout映像も大量に遅延破棄されました。Releaseビルドの20秒再試験でも同じ結果でした。最初の接続で音声433,823フレーム再生、879,648フレーム破棄、Spout映像497フレーム受信中379フレーム破棄です。30秒以上のループバック試験はこの状態を失敗と判定するよう変更しました。このVB-Matrix仮想ASIO環境ではPortAudioのASIO出力を採用確定できません。ドライバ設定と別のASIO実機で、申告レートと実効コールバック速度を再測定します。

30秒のWASAPI共有ループバックでは、補正器が5秒の基準測定後に有効になり、終盤の推定補正量は約−58 ppm、基準からの音声キュー先行量変化は約2.9 msでした。PortAudio underflowと時刻付きキューの破棄は0です。実際の送信側とデバイスのクロック差を外部基準で測った値ではありません。±100 ppmの仮想クロック差を1時間分進める単体試験では、補正量が逆方向へ収束し、先行量の誤差が20 ms以内でした。

ReleaseビルドでSRT受信遅延20 ms、受信バッファ容量256 KiB、音声・Spout出力遅延各100 msを設定し、別の仮想WASAPIデバイスへ20秒間ループバックしました。最初の接続で音声910,785フレーム、Spout映像474フレームを出力し、PortAudio underflow、音声フレーム破棄、Spout映像破棄はいずれも0でした。ログ上のSpoutと音声メディア時刻の最大差は約5.1 msです。この差はアプリ内の推定値であり、物理的な出力間の時差や送受信の総遅延を示しません。

音声復帰の短時間試験では、VB-Audio Virtual CableのWASAPI排他出力を別プロセスが8秒間占有しました。ROODは `Pa_OpenStream: Invalid device` を記録し、1秒間隔で同じ名前・ホストAPIの出力を探して再試行しました。7回目の開設で復帰し、最初のSRT接続が切れる前に音声コールバックとデコード済みフレームの消費を確認しました。これは開設時の利用不可からの復帰であり、再生中の物理的なデバイス切断を証明しません。

ループバック送信に使うFFmpegのSRT callerは、待受中でも初回接続が時々失敗しました。検証スクリプトは短い間隔で最大3回再試行します。libsrtの切断・再接続条件と失敗理由は、接続監視を仕上げる際に調査します。

| 項目 | 方法 | 合格判断に必要な記録 |
| --- | --- | --- |
| ASIO多チャンネル | 実際に使用するASIOドライバで4/8/16chを列挙・形式確認し、全チャンネルに識別信号を出す | デバイス名、ドライバ版、利用可能数、割り当ての実出力 |
| WASAPI共有／排他 | 同一機器で希望サンプルレート・チャンネル数・バッファ長を確認 | 開閉成否、報告遅延、連続出力時のunderflow |
| 出力時刻精度 | コールバック時刻と `outputBufferDacTime` の連続性を記録し、可能ならループバックで物理出力と照合 | ずれ・ジッター・後退・欠落の分布 |
| 長時間同期 | 送信側と別クロックで1時間以上のSRT入力を再生し、音声・映像の時差を継続記録 | ドリフト量、補正量、最終的な時差 |
| デバイス切断復帰 | 再生中の切断、既定デバイス変更、同名再接続を試す | エラー遷移、無音化、再列挙と復帰の所要時間 |

上記が通るまで、PortAudioを最終採用と宣言しません。タイムスタンプはPortAudio APIが示す「先頭サンプルのDAC出力予定時刻」で、ここで実測した物理時刻ではありません。[PortAudioの時刻情報](https://portaudio.com/docs/v19-doxydocs/structPaStreamCallbackTimeInfo.html)。
