# ROODのアーキテクチャと実装順

## 境界

```
SRT receive (libsrt) -> connection monitor / statistics
    -> demux / decode (FFmpeg: stream ID と channel layout を維持)
    -> timestamped queues / jitter and output-delay control
    -> common media timeline / drift estimator
       |-> audio router -> PortAudio (ASIO / WASAPI)
       |               `-> OMT audio channels
       `-> video scheduler -> Spout2 (Windows)
                            `-> OMT sender (libomt + libvmx)

Qt Widgets: 設定と接続・出力状態の表示のみ
```

音声デバイスを使う構成では、その消費速度を同期の基準にし、音声タイムラインの先行量からクロック差を推定してリサンプル比をゆっくり調整します。最初の5秒で先行量の基準を取り、補正は±500 ppmに制限します。Spout映像とOMTの映像・音声は、音声コールバックから推定したメディア時刻に合わせます。OMTの出力遅延は、音声の設定遅延との差分を加えます。OMTだけの出力、または音声デバイスが使えない間はホストの単調時計を基準にします。PortAudioの `outputBufferDacTime` は観測値として使い、正確な物理出力時刻と決めつけません。デバイス再接続時のクロック再確立と長時間の実機検証が必要です。

`ChannelRouter::render()` は**同期・サンプルレート変換後**の同じフレーム区間を入力に取ります。複数トラックはIDで区別し、各チャンネルを出力チャンネルへ複製・加算できます。未着トラックは無音です。ここにはSRTやQt、Windowsのヘッダーを含めません。

SRT受信遅延 `SRTO_RCVLATENCY`、受信バッファ容量 `SRTO_RCVBUF`、音声出力遅延、映像／音声オフセットは別の量として設定します。接続統計の `receiveBufferMs` / `receiveBufferBytes` は容量ではなく使用量です。低遅延時に安定する設定値は実機計測後に決めます。

接続監視では状態遷移、切断・再接続、受信ビットレート、RTT、損失・再送、受信キューを記録します。libsrtの統計API `srt_bstats` を監視入力に使い、GUIと将来のヘッドレス版へ同じ診断値を公開します。[libsrt API](https://github.com/Haivision/srt/blob/master/docs/API/API-functions.md)

OMTは**デコード後の映像・音声をネットワークに分配する出力**として加えます。複数のSRT音声トラックは、OMT出力ごとのルーティング設定で最大32チャンネルの音声バスへ写像します。映像のピクセル形式、フレーム時刻、音声との同期、接続先ごとの状態を扱います。[OMT公式の開発ガイド](https://github.com/openmediatransport)ではC/C++向け `libomt` と映像用 `libvmx` が案内されています。

Spout、音声デバイス、OMTの各出力に独立したキューと異常時の破棄方針を持たせます。ネットワーク側の遅い受信者が、ローカル音声と映像の出力スレッドを止めない構成にします。

SRT配信機能は現段階の開発範囲から外します。

## 次の実装順

1. PortAudioのASIO多チャンネル、WASAPI共有／排他、時刻情報、長時間同期、切断復帰を実機で評価する。使用するASIO SDKと公開条件を確定する。
2. 固定したライブラリ版でSRT受信とFFmpegのdemux/decodeを接続し、音声トラックID・チャンネルレイアウト・PTSを保持する。**MPEG-TSのlistenerモードで初期実装済み。** デコードフレームを呼び出し側へ渡すAPIを用意し、CLIでストリーム構成とSRT統計を確認できる。callerモードや他のコンテナは未検証。
3. タイムライン、受信バッファ、遅延制御、ドリフト補正を実装し、音声をPortAudioへ出す。**時刻付きの有界音声キュー、複数トラックのチャンネル合流、サンプルレート変換、指定出力遅延、WASAPI／ASIO出力、緩やかなクロック差補正を初期実装済み。** 低遅延設定の短時間試験と、1時間の同一PC内WASAPIループバックを通した。別クロックの実機での長時間同期と実機切断復帰は未検証。
4. 接続監視と再接続を実装し、入力ごとの統計と遅延を公開する。**接続・切断・再待受と、libsrtの受信速度、RTT、損失、再送、受信キューをGUIとCLIに表示し、GUIには直近50件の状態履歴も表示。** 読み取りはSRTのイベント監視で200 msごとに停止・切断を確認する。異常分類と複数入力は未実装。
5. 映像をSpout2へ出し、音声との表示時刻差を測る。**Spout2送信と別プロセスでの実フレーム受信を確認済み。** 音声コールバックの推定メディア時刻に映像PTSを合わせる。物理的な映像表示時刻とDAC出力時刻の差は未測定。
6. OMTへ映像と最大32チャンネルの音声を出し、受信側で同期とチャンネル対応を検証する。**別プロセスの受信器で映像と32チャンネル音声を取得し、0番と31番に別トラックの信号が届くことを確認済み。** 2分間の同時出力ではOMT映像・音声のタイムスタンプ幅が一致し、逆行もなかった。別クロック間の長時間同期とネットワーク負荷時の挙動は未検証。
7. Qt Widgetsへ設定と診断値を接続し、デバイス切断／SRT再接続を扱う。**待受開始・停止、出力設定、接続・トラック・統計表示と、音声出力の再列挙・再開設を実装済み。受信統計の更新時にも音声出力の稼働を確認する。** 一時的な排他占有からの復帰と、Debug版で再生中のストリームを停止させて再開設する試験は、同じSRT接続中に確認済み。設定はユーザー別のQt INIファイルへ保存・復元し、音声デバイスは識別子で再選択する。稼働中の実機切断と既定デバイス変更は未検証。

Linux小型ボード版ではSRT・FFmpeg・同期・ルーティングを再利用し、映像と音声の出力アダプターを差し替えます。SyphonとNDIは将来の検討項目です。
